# 接入外部 Web 系统

> 本文只讲**机制**。具体的系统地址、账号口令属于私有信息，
> 只存在用户本机的数据目录里，**不进仓库**。

## 一、能接什么

只支持一类：**带 JSON API 的单页系统**（自研或定制开发的后台）。

它们的共同点：

- 前端是 React / Vue 之类的 SPA，数据全部走 `/api/...`；
- 登录是一个 POST 接口，交出「账号 + 口令」，拿回一个 token；
- 之后每个请求带 `Authorization: Bearer <token>`。

**接不了的**（别指望自动接上）：

| 类型 | 为什么接不了 |
|---|---|
| 验证码 / 扫码登录 | 需要真人参与 |
| OAuth / SSO 跳转 | 涉及第三方授权，不是「账号+口令」 |
| 只有服务端渲染的传统页面 | 没有 JSON 接口，得解析 HTML，极脆 |
| 有重风控（设备指纹、行为检测） | 自动化会被判定异常 |

对这些系统，硬做出来的功能会「看着能用、实际天天挂」，不如不做。

## 二、用户怎么加

设置 → 系统接入 → 添加系统：

1. 填**网址 + 账号 + 口令**；
2. 点「试连接」——服务端会真的去登一次；
3. 连上了才能保存；连不上会说明原因（账号错 / 找不到接口 / 超时）。

连不上时展开「手动指定登录字段」，可以填：
- 账号字段名（`account` / `email` / `username` …）
- 密码字段名（`password` / `passwd` / `pwd` …）

自动探测有尝试次数上限（20 次），冷门字段组合可能排不进预算 ——
这时手填一次就能成，比让程序盲试 200 次更靠谱。

## 三、存在哪

```
<数据目录>/state.json → sites[]
```

一条记录长这样（口令只在这里，**不下发客户端**）：

```json
{
  "id": "site_xxx",
  "name": "我的系统",
  "baseUrl": "https://example.com",
  "auth": {
    "kind": "json",
    "loginPath": "/api/auth/login",
    "accountField": "account",
    "passwordField": "password",
    "tokenPath": "accessToken",
    "header": "Authorization",
    "scheme": "Bearer"
  },
  "account": "...",
  "password": "...",
  "teamRoomId": "r_xxx"
}
```

`tokenPath` 是 token 在登录响应里的位置，支持点号路径（`data.token`）。

## 四、bot 怎么用

每个 bot 有两个工具：

```
list_sites                                          看接了哪些系统
query_site(site, path, query)                       去查一个接口
```

例子（模型自己拼参数）：

```
query_site(site="我的系统", path="/api/rankings",
           query={ window: "1y", sortBy: "return", sortDir: "desc" })
```

服务端负责：

1. 查 token 缓存；没有或过期就登录换新；
2. 拼 `Authorization: Bearer`；
3. 遇到 **401 重登一次**再重试（404 / 500 不重登，重登也没用）；
4. 把 JSON 还给 bot。

结果超过 12000 字符时截断并告诉模型「结果较大，加筛选或翻页」，
避免把上下文撑爆。

## 五、一个系统 = 一个团队

给系统点「建团队」会创建一个部门，里面只有一个 bot，人设是
「负责这个系统的数据查询」。用户以后直接对它说需求就行。

不自动塞一堆角色：人多会互相推诿，而「查数据」这件事一个人就够。

## 六、容错（必须知道）

对方的接口没有版本承诺，**随时可能改**。集成层已经处理：

| 情况 | 表现 | 处理 |
|---|---|---|
| 接口路径变了 | 404 | 报「查 xx 失败」，不静默 |
| 字段改名 | `undefined` | bot 看到缺字段会说「这项数据没有」 |
| token 过期 | 401 | 自动重登一次 |
| 返回 HTML 而不是 JSON | —— | 提示「可能需要重新登录或接口变了」 |
| 口令改了 | 401/400 | 去设置里重新试连接 |
| 被限流 | 429 | 报错，不无限重试 |

## 七、安全约束

- 站点地址只接受 `http/https`；**拒绝本机与内网地址**
  （`127.0.0.1` / `10.x` / `192.168.x` / `172.16~31.x`），防 SSRF；
- 口令只存服务端本地，接口返回给客户端的只有 `hasPassword: true`；
- 登录请求不带缓存（`cache: no-store`）；
- 探测连续失败有次数上限，不打爆对方接口；
- 响应体积上限 4MB，超了截断，防对方返回巨表吃满内存。

## 八、排错

**「找不到登录接口」**
对方可能不是 JSON API 型系统，或者登录路径很特殊。
展开「手动指定登录字段」填字段名；还不行就说明这类系统接不了。

**「账号或口令不对」**
先确认能在浏览器里登录。注意有的系统首次登录要改密码。

**「连不上这个地址」**
检查网址是否完整（要带 `https://`），以及本机网络能否访问。

**之前好好的，现在不行了**
多半是对方改版了。点「测试连接」看具体错误；如果接口确实变了，
需要重新探测一次字段。
