# Agent 能力机制与实现边界

第一至四节描述能力设计目标与机制取舍，不代表全部已实现；当前实现状态与边界见第五节。

---

## 1. 安全与权限

- **命令先解析，再判定**：把一条命令拆成"可执行体 + 参数 + 子命令"，再拿规则去匹配，
  而不是对整串字符做前缀比较。匹配失败时还能给出"这条可以加进白名单"的建议。
- **匹配前归一化**：去掉不可见字符，还原引号与转义（`'…'` / `"…"` / `$'…'` / `\xNN` / `\ `）。
  否则 `r''m`、`\rm`、`"rm"` 这类改写就能绕开规则。
- **不透明命令检查**：命令替换、反引号、heredoc、进程替换的内容可能到运行期才确定；
  设计目标是拒绝无法静态判定的操作，并统一命令检查与审批的执行顺序。
- **策略分层**：用户 / 仓库 / 团队各有一层配置，合并后仍能追溯每个字段来自哪一层。
  被拒命令可以单独留档，便于事后审计。
- **沙箱不可用要显式返回**，不允许静默降级成裸跑。

## 2. 执行层

- **长任务是一等公民**：命令可以转后台，拿到句柄与 pid，之后还能往 stdin 写；
  超时、被拒、权限不足、启动失败各自有结构化结果，前端据此决定重试还是换路径。
- **输出模式通知**：给长任务挂一个匹配模式（例如出现错误、出现"已启动"），
  命中时通知一次，支持去抖与次数上限 —— 模型不用反复轮询。
- **截断带元数据**：返回结果里带总行数、输出行数、字节数、是否首行就超限、
  末行是否被截；搜索结果还分别标记"客户端截断 / 引擎截断 / 是否应用了首行限制与偏移"。
  模型因此知道"我被截了、还剩多少、从哪儿续"。

## 3. 扩展点

- **Agent 是可配置对象**：除了人设，还有技能、子 agent、钩子、规则、命令、MCP 服务器。
- **技能带调用控制**：有来源（仓库 / 插件 / 市场）、环境限制、glob 作用域，
  并且可以分别关闭"模型自动调用"和"用户手动调用"。
- **钩子能改输入**：工具调用前可以拒绝、可以改写入参、可以追加这一轮的上下文；
  子 agent 是异步对象，等待有超时，超时返回"仍在运行 + 转写位置"而不是当成失败。

## 4. 会话与任务

- **任务板**：任务有状态、已读边界、置顶，完成后仍可查看（不是一结束就消失）。
- **自动化**：挂在 agent 上的定时任务，可启停、带时区。
- **附件**：分片上传与分片读取，带哈希校验。
- **运行中状态**：当前动作（工具 + 目标 + 调用 id）与"在等什么、等了多久"。
- **增量同步**：转写用游标 + 代数，游标过旧时给明确结果，让客户端整表重读。

## 6. 实现边界

- 命令规则使用 `exe:args` 语法，匹配前进行归一化与解析；拒绝结果返回可展示的原因。不带通配符时，短选项拆开后按「规则选项 ⊆ 命令选项」匹配，位置参数按词前缀。两条规则都空着时不改变原有放行；配了规则后，`sh -c` / `bash -c`、`xargs <命令>` 和解释器会拒绝（解释器只放行版本和帮助）。脚本文件、Makefile、npm scripts 里的命令不在检查范围内。`awk` 的 `system`、`vim -c`、`npx`、`make` 等间接执行没有列全，严格限制请用白名单或“需要批准”。沙箱另行立项。
- 调度决策、输入校验等纯逻辑独立成模块，执行层负责网络、进程与持久化副作用。
- 新增机制须明确输入、输出、失败路径与资源预算，并补充相应测试。
