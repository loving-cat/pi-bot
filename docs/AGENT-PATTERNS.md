# agent 能力的机制与我们的规划

> 这份文档记录我们自己认可的机制取舍：为什么这么做、我们怎么做、哪些暂不做。
> 所有命名、规则语法、文案、实现都是本项目自己的。

---

## 1. 安全与权限

- **命令先解析，再判定**：把一条命令拆成"可执行体 + 参数 + 子命令"，再拿规则去匹配，
  而不是对整串字符做前缀比较。匹配失败时还能给出"这条可以加进白名单"的建议。
- **匹配前归一化**：去掉不可见字符，还原引号与转义（`'…'` / `"…"` / `$'…'` / `\xNN` / `\ `）。
  否则 `r''m`、`\rm`、`"rm"` 这类改写就能绕开规则。
- **判不了就拒绝**：命令里含命令替换、反引号、heredoc、进程替换时，内容要到运行期才确定；
  这种命令按拒绝处理，并且**不能就地批准**（只能由用户在终端里手动执行）。
- **策略分层**：用户 / 仓库 / 团队各有一层配置，合并后仍能追溯每个字段来自哪一层。
  被拒命令可以单独留档，便于事后审计。
- **沙箱不可用要显式返回**，不允许静默降级成裸跑。

## 2. 执行层

- **长任务是一等公民**：命令可以转后台，拿到句柄与 pid，之后还能往 stdin 写；
  超时、被拒、权限不足、启动失败各自有结构化结果，前端据此决定重试还是换路径。
- **输出模式通知**：给长任务挂一个匹配模式（例如出现错误、出现"已启动"），
  命中时通知一次，支持去抖与次数上限 —— 模型不用反复轮询。
- **截断带元数据**：返回结果里带总行数、输出行数、字节数、是否首行就超限、
  末行是否被截；搜索结果还分别标记"客户端截断 / 引擎截断 / 是否应用了首行限制与偏移"。
  模型因此知道"我被截了、还剩多少、从哪儿续"。

## 3. 扩展点

- **Agent 是可配置对象**：除了人设，还有技能、子 agent、钩子、规则、命令、MCP 服务器。
- **技能带调用控制**：有来源（仓库 / 插件 / 市场）、环境限制、glob 作用域，
  并且可以分别关闭"模型自动调用"和"用户手动调用"。
- **钩子能改输入**：工具调用前可以拒绝、可以改写入参、可以追加这一轮的上下文；
  子 agent 是异步对象，等待有超时，超时返回"仍在运行 + 转写位置"而不是当成失败。

## 4. 会话与任务

- **任务板**：任务有状态、已读边界、置顶，完成后仍可查看（不是一结束就消失）。
- **自动化**：挂在 agent 上的定时任务，可启停、带时区。
- **附件**：分片上传与分片读取，带哈希校验。
- **运行中状态**：当前动作（工具 + 目标 + 调用 id）与"在等什么、等了多久"。
- **增量同步**：转写用游标 + 代数，游标过旧时给明确结果，让客户端整表重读。

## 5. 我们的实现与差异

| 机制 | 我们的做法 | 状态 |
|---|---|---|
| 命令解析 + 归一化 + 通配规则 | `server/src/shell-policy.js`（纯函数） | ✅ 已实现 |
| 判不了就拒绝 | 同上，返回结构化原因，文案明确"不能在这里批准" | ✅ 已实现 |
| 拒绝留档 | `store.addDenial/listDenials`，`/api/state` 带 `denials` | ✅ 已实现 |
| 拦截点 | pi 内联扩展拦 `tool_call`（`server/src/policy-hook.js`） | ✅ 已实现 |
| 转写游标 + 代数 | 不采用：会话转写由 pi 维护，服务端只做快照与增量推送 | 跳过 |
| 后台 shell + 输出模式通知 | — | 待做 |
| 截断元数据 | — | 待做 |
| 钩子（改入参 / 追加上下文） | 我们已有 `tool_call` 拦截，可在此基础上扩 | 部分 |
| 任务板 / 自动化 / 附件分片 | — | 待做 |

**明确不做**：通话（接听/挂断）隐喻、浏览器实时语音那套事件协议，以及任何第三方产品的命名与文案。

## 6. 实现边界

- 只学"为什么这样设计、取舍是什么"，然后按我们的产品形态重写：
  我们的规则语法（`exe:args`）、拒绝文案、函数与文件命名都是自己的。
- 不引入第三方代码、长段原文、内部类型名或界面文案。
- 新增机制先写清"机制是什么、取舍是什么"，再落到我们的模块里；必要时先写测试再动代码。
