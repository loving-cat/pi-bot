## §13.2 具体是什么（规格原话五步）

1. **展示主 Bot 的全机任务视野** + 当前普通用户身份 + computer use 的**实际系统权限**；
   说明危险动作确认不被取消
2. 用户选择**负责人项目**和**普通 Git 动作范围**；明确远端操作、共享元数据、
   hooks/签名及凭据使用是否另需批准
3. 为执行 Bot 分配**任务级最小权限**和执行模式；普通桌面通用键鼠权限**不随角色继承**
4. 开始前**汇总本次有效权限**、到期/撤销条件、需逐次确认的动作、**不能提供的硬隔离保证**。
   OS 授权失败按实际结果报告，不自动切换更宽模式
5. 完成后展示产物、实际测试边界及副作用，**级联回收临时权限**；
   用户可保留明确项目授权，但不能从"保留项目"推导长期对外发送或付款权限

### 动手前先想清楚三件事

  （建议一页：五步里有三步是"告知"，只有一步是"选择"）
- **数据**：现有 `store.policy()` / `store.state.grants` / `config.tools` 足够；
  但"首次"这个状态没有存的地方 —— 需要一个新的 `state.onboarding` 字段
- **不做**：不要在这一版顺手改权限模型。§13.2 是**展示与引导**，
  不是新授权机制（规格 §16.2 明确「这些是设计默认，不是新增授权」）

## 一个可能挡路的已知问题

本机装着 **GameViewer 远程控制**，它持续合成输入 ——
`GetLastInputInfo` 永远报"刚刚有人动"，于是接管检测永远让开，
`desktop_input` 第一次永远发不出去，而文案说的是"用户在动"（用户会以为是自己碰的）。

现在 `desktop_lease status` 会点名说出来。要真正解决得二选一：
关掉 GameViewer，或者你决定"信任这台桌面"（那是产品决策，我没偷偷放宽）。
