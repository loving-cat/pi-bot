# pi-bot 1.1.0 全量复审（2026-10-17 第二版）

对象：`server` 1.1.0（10037 行，45 个源文件）、`app` 1.1.0+1、`dist/` 与磁盘上的分发包。
方式：回归核销（拿上一版体检的 13 条逐条判「已修 / 未修 / 变了」）+ 新模块首检 + 全量跑测试。
隔离：测试用独立端口与独立数据目录，线上 `data/` 未改动，实例跑完已清理。

## 一、总判定

**安全补上了、性能上去了、编排原地踏步、发布没跟上。**

| 维度 | 结论 |
|---|---|
| 安全 | 上一版最要命的鉴权裸奔 **彻底修好**，还多加了 DNS rebinding 与 CSRF 两道；但新增的公网中转默认无口令 |
| 性能 | bench 全线提速 40~56%，单条消息固定上下文开销降 31.7%；上一版判定的"同步落盘阻塞流式" **被实测推翻** |
| 编排 | 上一版点名的 5 条旧账 **一条没修**，属于搬家不是修 bug |
| 发布 | **磁盘上没有任何一个 1.1.0 的可分发产物**，`dist/` 里还是 0.1.0、缺 15 个模块 |
| 质量基建 | 测试脚本 10 → 33 个，单测 104 → 168，全绿；但有 4 条"假绿" |

## 三、P0（会直接被用户撞上，且其中一条已经踩中）

**P0-1 磁盘上没有 1.1.0 的可分发产物**
`dist/pi-bot-windows/server/package.json` = **0.1.0**，`server/src` 只有 30 个文件（当前 45 个，缺 `relay/`、`hooks.js`、`shells.js` 等 15 个）。磁盘上最新包是 `v1.0.5.zip` / `v1.0.6.apk`，而代码与 App 都已是 1.1.0。打包脚本本身没问题，是**没人重跑**。
→ 现在把 `dist/` 或那两个包发出去，发的是旧一代服务端。

**P0-2 端口被占用时进程不退出也不报错，变成"活着但没在听"的僵尸**
`server-main.js:89` `server.listen()` 没挂 `error` 事件，EADDRINUSE 冒到 `:53` 的 `uncaughtException` 兜底 → 记一行日志继续跑：不监听、不打印地址、pid 照写、后台还在探活。桌面端靠"进程退出"判启动失败（`:58`），进程不退 ⇒ **永远不报失败**，用户看到的是无限转圈。实测确实打出了 `未捕获异常（进程继续跑）：Error: listen EADDRINUSE`。
→ 一行修法：`:89` 前挂 `server.on('error', err => { log(...); process.exit(2); })`。

**P0-3 公网中转默认不校验口令，code 泄露即可挤掉主人并截走 token**
`relay/server.js:107` `if (secret && !sameSecret(given, secret))` —— secret 为空串时整句短路，不做任何校验；`relay-server.js:12-15` 未设口令只打一行警告就照常监听 `0.0.0.0`；`:112-116` 同名 code 后到者**静默替换**先到者，而手机的 `authorization` 会原样透传给挂着的那个客户端（`:344`）。
→ 攻击者用泄露的 code 先挂上，主人电脑被静默踢下线，手机发来的 token 全部落到对方手里，且手机端无感知。
→ 修法：空口令拒绝启动；同名 code 不再静默替换，改为拒绝 + 告警。
（正面：帧大小上限、解压炸弹防护、code 爆破防护都做得不错，12 位 hex 扫不出来。）

## 四、P1（直接降低工作质量 / 明确的功能 bug）

**P1-1 群记录 1600 字硬截断，正在吃掉派活正文**
`group-prompt.js:109` 无差别 `slice(0, 1600)`。本轮房间实测：13 条消息里 5 条超长，**整体保真率 61.2%**；架构师 2530 字的派活被砍 930 字，`@算法工程师` 恰在第 2032 字处被砍掉。这不是假设——**这一轮的派活正文就是断的**，受派人只能靠猜范围干活。4236 字的报告别人只能看到 1600 字（丢 62%）。
→ 改法：单条不硬截，改按总预算截；先保「用户 / 部门老大」全文，再截同事长结论的尾巴并标注截掉多少。
→ 指标：派活正文完整率 100%，群记录保真率 ≥95%。

**P1-2 游标失效两处（旧 #3a / #3b，一字未改）**
- `pi-runner.js:878` 预算掐断后，排队但没轮到的人照样 `setCursor(lastId)`，派活正文被越过 → 下次被叫只剩"X 叫了你"；
- `pi-runner.js:828` 先写游标、`:839` 才删消息，`store.js:1364` 的 `deleteMessage` 不清游标，`group-prompt.js:57` 找不着就 `start=0` 回退 → 下一次把最多 30 条旧消息当新任务重读（本轮实测代价：11 条 / 9900 字符）。
→ 改法：排进过队列的人不推游标；`deleteMessage` 同步把指向该 id 的游标重设为前一条。

**P1-3 群里仍然能走私信（旧 #8）**
`session-factory.js:73` 建工具时没传房间类型，`tools.js:339` 的 `message_bot` 在群里照样可见，而提示词 `group-prompt.js:123` 又写着"必须用 @，不要用 message_bot"。同一份提示一边禁止一边给工具。
→ 可复用 `ask_user` 的群聊调用限制（`tools.js:193-201`），为对应工具增加相同的场景校验。

**P1-4 空回复兜底第二层在别人机器上静默失效（旧 #6）**
`pi-runner.js:1283-1287` 仍是 `[this.model, selfhost/…, selfhost/…]`；换 provider 后后两个解析为 null 被 `filter(Boolean)` 滤掉，链里只剩刚吐空的那个模型。

**P1-5 终止时留下永久转圈的空白消息（旧 #9）**
`pi-runner.js:1034-1046` 先建 streaming 消息 + typing，`:1193` 才判 `aborting` 并 return，`:1197` 的 `busy=true` 在其后 → 消息永远转圈、typing 永远亮、`busy` 从没置 true，看门狗够不着，只能重启收掉。

**P1-6 数据目录迁移把 300MB 原样复制一份**
`config.js:37-46` `cpSync` 递归拷贝，filter 只排除 `_` 开头，`workspace/`（283MB，含 .venv 250MB）整个被搬，且在启动路径上同步执行；旧目录"留着当备份"但没有任何清理入口。现场：两处各 ~300MB，实占 ~590MB。
→ 改法：只搬 `state.json` / `rooms/` / `sessions/` / `uploads.json`，不搬 `workspace/`，搬完写标记并提示可删旧目录。

## 六、测试基建的「假绿」

跑通不等于测到。以下 4 条建议一并修：

1. `tests/unit.mjs:440` 恒真断言：`assert.equal(x, cond ? x : '')` —— 拿 x 跟自己比，用例名要验的"退回默认值"从没验过。
2. `tests/bench.mjs` 零断言、永远退出 0：`脏房间数：1` 那句是注释不是断言，增量落盘退化也拦不住。
3. `tests/smoke.mjs` 只看 `status === 'done'`，不校验正文是否为空 —— 而"绝不给你空白"正是产品承诺。
4. `tests/auth.mjs:167`：`lan` 为空时 4 条远程 401 用例直接不进统计，报告仍是全绿 —— 换台没局域网地址的机器跑，最重要的用例会静默消失。

另：`tests/extract.mjs` 不在 `all.mjs` 里，附件解析没有默认回归保护；`npm test` 只挂 22 个脚本而目录里有 32 个。README 数字漂移：单测写 104（实际 168）、脚本写 17 个（实际 22）。

## 七、建议的修复顺序

1. **发布链**（P0-1 + P0-2）：重打包并校验版本与模块数；端口占用改为退出码 2。成本半天，堵住"发错包"和"永远转圈"。
2. **中转口令**（P0-3）：空口令拒绝启动 + 拒绝静默替换。成本几行，堵住 token 被钓走。
3. **群记录截断**（P1-1）：直接提升整个部门的工作质量，改法明确、可量化。
4. **游标 + 群里私信 + 兜底链 + 终止留白**（P1-2~P1-5）：都是十行内的确定 bug。
5. 其余 P2 与假绿测试按周排。
