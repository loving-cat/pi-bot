# 规格：意图分档与用户习惯（v1，**最高优先级**）

> 2026-11-16 立。**优先级 P0 —— 排在其它所有待办之前。**
>
> 这份规格补的是 `spec-permissions-v1.0.1.md` §5.6 没写清的一件事：
> §5.6 按**能力**分了 T0/T1/T2 三档，但没说**什么时候该用哪一档**。
> 结果就是：bot 用"用户可见的浏览器"去做本该后台完成的调研，
> 在用户的屏幕上点来点去、进全屏、留下一个用户退不出去的状态。
>
> 与旧规格的关系：
> - 不新增授权机制（§6.1 不变，授权根仍然只能来自用户交互）；
> - 不改变 §5.6 的三档能力边界，只定义**选择判据**；
> - 新增"用户习惯"这一层记忆，属于 §13.1 四层配置里的"用户覆盖"之外的一层，
>   但**不是配置**（不由用户手填，由对话里学出来、可随时纠正）。

---

## 1. 一条判据决定前台还是后台

> **这个结果要不要用户用眼睛看？**

| 答案 | 用什么 | 落点 | 用户能看见 |
|---|---|---|---|
| 要 | `ego_browser`（用户那只浏览器） | **前台**，窗口可拖、可关、可 Esc | ✅ |
| 不要 | **岛**（`desktop_island_*`）或 `web_fetch` | 后台桌面 / 无界面 | ❌ |

**为什么只留一条判据**：判据越多，模型越会在两条之间摇摆，而"摇摆"的代价
是用户被莫名其妙弹一脸窗口。"要不要用户看见"是唯一**可机器复核**的问题
（看它用了哪个工具就知道了）。

### 1.1 反例（必须能判出来）

| 说法 | 该走哪档 | 判据 |
|---|---|---|
| "帮我打开 B 站热门第一条，我要看" | 前台 ego | 用户要看 |
| "查一下 B 站现在热门第一是什么" | 后台（岛 / web_fetch） | 用户只要答案 |
| "登录我的淘宝，帮我看下订单" | 前台 ego（要登录态）+ 用户在场 | 用户要看/要确认 |
| "抓 100 个商品的价格" | 后台 | 用户只要数据 |
| "把这个页面截图给我看" | 后台截图 → 发图片给用户 | 用户要看的是**图**，不是那个窗口 |

最后一行是关键：**"用户要看结果" 不等于 "用户要看那个浏览器窗口"**。
能给一张图/一段结论，就别把窗口弹出来。

## 2. 前台模式的三条硬约束（ego）

前台意味着"在用户的屏幕上动"，所以：

1. **不许进全屏**：不请求 `requestFullscreen()`，不点会触发全屏的位置
   （视频中心双击、播放器的全屏按钮）。
2. **交还前必须退出全屏**：这一条**服务端强制执行**，不靠模型自觉
   （`ego-browser.js` 在脚本结束后跑一次收尾：所有 TaskSpace 的页面
   `document.exitFullscreen()`）。
3. **交还时必须停在"可接手"状态**：普通窗口（有标题栏）、可以拖动、
   有明确的关闭入口、按 Esc 能退出任何全屏/覆盖层。

> **底线**：任何"用户退不出去"的界面都是 bug。一次真实的故障：
> bot 用 ego 打开 B 站热门视频去"验证播放"，点了视频中心触发全屏，
> 交还控制权后用户面对一个满屏黑底、没有标题栏、拖不动的窗口。

## 3. 用户习惯（preferences）

### 3.1 它和已有两种记忆的区别

| 层 | 内容 | 谁产生 | 例子 |
|---|---|---|---|
| 经验 `lessons` | "这种事这样做" | 复盘候选 → 用户启用 | "配班子先按模块拆 owner" |
| 记忆摘要 | 聊过什么 | 自动总结 | "昨天在调 B 站播放" |
| **偏好（新增）** | **这个人的习惯** | 用户纠正 / 明确表达 / 重复选择 | "看视频直接放前台，别全屏" |

偏好**直接生效**（不像经验要手工启用），因为：
- 说错了最多是"下次按这个来"，用户在对话里说一句就能改回来；
- 而经验写歪会固化错误做法，所以必须人工兜一道。

### 3.2 什么情况下记（只有这三种，防止噪音）

1. **用户纠正**："别用我的浏览器" / "不要全屏" / "这种应该后台跑" → `strength: strong`
2. **用户明确表达**："以后都用 ego" / "我习惯先看结论" → `strength: strong`
3. **同一选择重复 3 次**（三次都是"打开给我看"）→ `strength: weak`

不记：一次性要求（"这次用 Firefox"）、事实（"我的账号是 x"）、
以及**没有证据的推断**（必须有原话，沿用 `lesson-reflect` 的证据校验）。

### 3.3 怎么用

- 注入系统提示的一节【用户的习惯】，**只放 strong 且最多 5 条**；
- weak 的**不进提示词**，只在设置页可见（供用户确认或删除）；
- 冲突时**以新的为准**，旧的标 `superseded`（不能让两条在 prompt 里打架）。

### 3.4 按谁记

偏好是**对人**的（全局），不是对某个 bot 的。49 个 bot 共享同一份"你的习惯"。
`scope: 'user'`（默认）之外，保留 `scope: 'bot:<id>'` 的位置但目前不用 ——
"这个 bot 擅长什么"属于经验，不属于偏好。

## 4. 验收

| 断言 | 怎么验 |
|---|---|
| 调研类请求不会打开用户浏览器 | 让主 Bot 查一个页面的标题，检查它用了岛/web_fetch 而不是 ego |
| 给用户看的请求会落在前台且可退出 | 让它"打开 B 站热门第一条"，交还后窗口有标题栏、Esc 能退、非全屏 |
| 全屏兜底不靠模型自觉 | 脚本里强行进全屏 → 收尾后 `document.fullscreenElement === null` |
| 纠正能变成偏好 | 说一次"以后别全屏"，下一次同类操作页面停在非全屏 |
| 偏好不污染 prompt | 注入条数 ≤ 5，且只含 strong |
| 新旧矛盾以新的为准 | 先后说"用 ego"/"别用 ego"，第二次生效、第一次标 superseded |

---

## 5. 不做的事

- 不做"自动猜用户想要前台还是后台"的黑箱评分 —— 判据就是一句话，可复核；
- 不让偏好变成授权（偏好永远不能放宽权限，只能影响**怎么用**已授的权）；
- 不在这一版做 per-bot 偏好（先证明人的偏好有用）。

### 有意留白 / 已知边界

- **岛的窗口消息驱动只对经典 Win32 可靠**：Chromium 自绘，`PostMessage` 点不到 DOM 元素。
  所以"后台浏览器"走 **CDP**（`--remote-debugging-port`），不走窗口消息；岛上的是有头真浏览器，
  窗口在用户看不见的桌面上。
- **无头会被一部分站点识别**（Cloudflare 之类）。默认 `mode: 'island'`（Windows），
  非 Windows 自动降级为无头。
- **非 Windows 没有岛**：`desktop_island_*` 明确拒绝并说明原因，不静默降级成"动用户鼠标"。
- **`mode: 'headless'` 不会同步登录态回本机**：快照是复制品，在后台浏览器里登录/退出不影响用户的浏览器。
